1. SRS DEEP ANALYSIS & ENTERPRISE REQUIREMENTS MATRIX
================================================================================

1.1 Core Entities & User Archetypes:
-----------------------------------
A. Fan User (Client Side):
   - Multi-platform exploration across 6 major fandom pillars:
     1. Anime & Manga (Cosplay, Graphic Novels, Shonen/Seinen lore)
     2. Gaming & Esports (Retro gaming, Open-world RPGs, Speedrunning records)
     3. Pop Culture, Movies & Sci-Fi Universes (Cinematic sagas, Marvel, Star Wars)
     4. Comic Books & Graphic Literature (Superhero lore, Indie comics)
     5. Music & Idol Culture (K-Pop bands, Discographies, Fan clubs)
     6. Fantasy & Literature (Novels, High-fantasy worldbuilding)
   - Beginner Fan Hub: Lore starters, Glossary of 50+ fandom terms, Pronunciations.
   - Deep Dive Lore: Hidden trivia, easter eggs, creator interviews, universe chronologies.
   - Location-Aware Event Radar: GPS convention finder, city filtering, Google Maps pins, direct external ticketing.
   - Official Fan Merchandise Store: Catalog, price sort/filter, wishlist, simulated cart, coupon engine, printable invoice bill with QR code.
   - AI Fan Assistant: Predefined FAQ fast answers + connected AI API (Google AI Studio / Gemini API) for conversational fandom queries.
   - Offline Bookmarking: SQLite local caching of articles, idol profiles, and lore for instant no-internet reading.
   - Community & Discussions: Topic boards, rating, upvoting, nested discussion replies.
   - Contact & About Us: Interactive enquiry form, organization history, team credits, Google Maps office marker.

B. Admin User (Management Console):
   - Pre-configured secure credential login (No open signup; role-based access control).
   - Real-time Analytics Dashboard: Total fans, active fandoms, trending products, upcoming events, system health metrics.
   - Content Moderation: Add, edit, delete articles, lore, news, glossary entries.
   - Event Management: Add, edit, delete conventions, venues, latitude/longitude coords, ticket URLs.
   - Merchandise Management: Add, edit, delete products, prices, stock levels, discount flags.
   - User Management: View fan accounts, toggle active/suspended status, audit logs.
   - Category Management: Create, update, re-order Fandom categories and custom icon/banner assets.

1.2 Non-Functional & Enterprise Constraints:
-------------------------------------------
- Performance: 60/120 FPS buttery smooth transitions, lazy-loaded lists (`ListView.builder`), cached images, sub-120MB baseline memory footprint.
- Offline-First: All bookmarked content, categories, and FAQs stored in local SQLite database for zero-latency offline access.
- Security: Role-based routing guards, token storage in `flutter_secure_storage`, parameterized SQL queries preventing SQL injection.
- Code Standards: Clean Architecture with Feature-First structure, SOLID principles, 100% type-safe Dart 3.6+, zero compiler warnings.

2.2 Zero-Conflict Routing Contract:
-----------------------------------
`lib/routes/app_router.dart` is written on Day 1 and NEVER modified again:
```dart
class AppRouter {
  static Route<dynamic> onGenerateRoute(RouteSettings settings) {
    // Check Fan routes first
    final fanRoute = FanRoutes.getRoute(settings);
    if (fanRoute != null) return fanRoute;

    // Check Admin routes
    final adminRoute = AdminRoutes.getRoute(settings);
    if (adminRoute != null) return adminRoute;

    return MaterialPageRoute(builder: (_) => const NotFoundPage());
  }
}
```
Developer A only adds routes inside `fan_routes.dart`.
Developer B only adds routes inside `admin_routes.dart`.
Result: 0% chance of route file git conflicts.

2.3 Zero-Conflict Dependency Injection Contract:
------------------------------------------------
`lib/core/di/injection_container.dart` is structured cleanly:
```dart
final sl = GetIt.instance;
Future<void> initDependencies() async {
  await initCoreDependencies(sl);
  await initDevAInjection(sl); // Handled in dev_a_injection.dart by Dev A
  await initDevBInjection(sl); // Handled in dev_b_injection.dart by Dev B
}
```

2.4 Git Branching & Workflow Rules:
-----------------------------------
1. `main` branch: Stable, runnable, production-ready.
2. `develop` branch: Integration branch.
3. Feature branches:
   - `feature/dev-a-auth-fandom-hub`
   - `feature/dev-a-events-ai-community`
   - `feature/dev-b-database-store-cart`
   - `feature/dev-b-admin-profile-deliverables`
4. Pull Request Rule: Never commit directly to `develop` or `main`. PRs merge cleanly because file paths are 100% disjoint.

6. DATABASE ARCHITECTURE: SQLITE DDL SCHEMA & SEED DATA (DEVELOPER B)
================================================================================

All 12 tables are implemented in SQLite local storage (`fandom_verse.db`) with full offline indexing:

```sql
-- 1. Users Table
CREATE TABLE IF NOT EXISTS users (
    user_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE NOT NULL,
    role TEXT NOT NULL DEFAULT 'fan', -- 'fan' or 'admin'
    avatar_url TEXT,
    bio TEXT,
    badges TEXT,                      -- JSON Array of string badges
    selected_fandoms TEXT,            -- JSON Array of selected categories
    created_at INTEGER NOT NULL
);

-- 2. Fandom Categories Table
CREATE TABLE IF NOT EXISTS categories (
    category_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    description TEXT,
    icon_name TEXT,
    banner_url TEXT,
    color_hex TEXT
);

-- 3. Posts & Lore Articles Table
CREATE TABLE IF NOT EXISTS posts (
    post_id TEXT PRIMARY KEY,
    category_id TEXT NOT NULL,
    title TEXT NOT NULL,
    content_body TEXT NOT NULL,
    author_name TEXT,
    image_url TEXT,
    is_trending INTEGER DEFAULT 0,
    is_deep_dive INTEGER DEFAULT 0,
    tags TEXT,
    timestamp INTEGER NOT NULL,
    is_bookmarked INTEGER DEFAULT 0,
    FOREIGN KEY (category_id) REFERENCES categories(category_id) ON DELETE CASCADE
);

-- 4. Fandom Glossary Table
CREATE TABLE IF NOT EXISTS glossary (
    term_id TEXT PRIMARY KEY,
    term TEXT NOT NULL,
    definition TEXT NOT NULL,
    fandom_category TEXT,
    example_usage TEXT
);

-- 5. Conventions & Events Table
CREATE TABLE IF NOT EXISTS events (
    event_id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    description TEXT,
    city_name TEXT NOT NULL,
    venue_name TEXT NOT NULL,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    event_date INTEGER NOT NULL,
    ticket_link TEXT,
    banner_url TEXT,
    is_bookmarked INTEGER DEFAULT 0
);

-- 6. Merchandise Catalog Table
CREATE TABLE IF NOT EXISTS merchandise (
    product_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    category TEXT NOT NULL,
    price REAL NOT NULL,
    original_price REAL,
    image_url TEXT NOT NULL,
    description TEXT,
    stock_count INTEGER DEFAULT 10,
    rating REAL DEFAULT 4.8,
    is_featured INTEGER DEFAULT 0
);

-- 7. Cart Items Table
CREATE TABLE IF NOT EXISTS cart_items (
    cart_id TEXT PRIMARY KEY,
    product_id TEXT NOT NULL,
    quantity INTEGER NOT NULL DEFAULT 1,
    selected_variant TEXT,
    added_at INTEGER NOT NULL,
    FOREIGN KEY (product_id) REFERENCES merchandise(product_id) ON DELETE CASCADE
);

-- 8. Wishlist Table
CREATE TABLE IF NOT EXISTS wishlists (
    wish_id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    product_id TEXT NOT NULL,
    saved_at INTEGER NOT NULL,
    FOREIGN KEY (product_id) REFERENCES merchandise(product_id) ON DELETE CASCADE
);

-- 9. Community Discussions Table
CREATE TABLE IF NOT EXISTS discussions (
    thread_id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    user_name TEXT NOT NULL,
    user_badge TEXT,
    category TEXT NOT NULL,
    title TEXT NOT NULL,
    body TEXT NOT NULL,
    upvotes INTEGER DEFAULT 0,
    created_at INTEGER NOT NULL
);

-- 10. Discussion Replies Table
CREATE TABLE IF NOT EXISTS discussion_replies (
    reply_id TEXT PRIMARY KEY,
    thread_id TEXT NOT NULL,
    user_name TEXT NOT NULL,
    reply_body TEXT NOT NULL,
    created_at INTEGER NOT NULL,
    FOREIGN KEY (thread_id) REFERENCES discussions(thread_id) ON DELETE CASCADE
);

-- 11. Celebrity & Star Profiles Table
CREATE TABLE IF NOT EXISTS star_profiles (
    star_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    fandom_category TEXT NOT NULL,
    role_title TEXT NOT NULL,
    bio TEXT NOT NULL,
    image_url TEXT NOT NULL,
    social_handle TEXT,
    is_bookmarked INTEGER DEFAULT 0
);

-- 12. Simulated Orders Table
CREATE TABLE IF NOT EXISTS simulated_orders (
    order_id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    order_date INTEGER NOT NULL,
    total_amount REAL NOT NULL,
    items_summary TEXT NOT NULL,
    shipping_address TEXT NOT NULL,
    order_status TEXT DEFAULT 'Completed'
);
```

Developer A BLoCs:
1. `AuthBloc`:
   - Events: `CheckAuthStatus`, `FanLoginSubmitted(email, pass)`, `FanRegisterSubmitted(name, email, pass)`, `AdminLoginSubmitted(email, pass)`, `LogoutRequested`.
   - States: `AuthInitial`, `AuthLoading`, `FanAuthenticated(user)`, `AdminAuthenticated(admin)`, `Unauthenticated`, `AuthError(msg)`.

2. `FandomHubBloc`:
   - Events: `LoadFandomFeed`, `SelectCategoryFilter(catId)`, `SearchContentQuery(query)`, `ToggleBookmarkPost(postId)`.
   - States: `FandomLoading`, `FandomFeedLoaded(trending, news, glossary)`, `FandomError(msg)`.

3. `EventBloc`:
   - Events: `LoadAllEvents`, `FilterEventsByRadius(km)`, `FilterEventsByCity(city)`, `ToggleEventBookmark(id)`.
   - States: `EventLoading`, `EventLoaded(events, nearbyEvents)`, `EventError(msg)`.

4. `AIAssistantBloc`:
   - Events: `SendUserQuery(message)`, `SelectFaqPrompt(prompt)`, `ClearChatHistory`.
   - States: `AIIdle`, `AITyping`, `AIMessageReceived(List<ChatMessage>)`, `AIError(msg)`.

5. `CommunityBloc`:
   - Events: `LoadDiscussionThreads(category)`, `SubmitNewThread(title, body, cat)`, `AddReplyToThread(threadId, reply)`, `UpvoteThread(id)`.
   - States: `CommunityLoading`, `CommunityLoaded(threads)`, `CommunityError(msg)`.

Developer B BLoCs:
1. `ThemeBloc`:
   - Events: `LoadSavedTheme`, `ToggleThemeMode(ThemeMode)`.
   - States: `ThemeState(ThemeMode.dark | light)`.

2. `StoreBloc`:
   - Events: `LoadProductCatalog`, `FilterProductsByCategory(cat)`, `SortProductsByPrice(ascending)`, `SearchProducts(query)`.
   - States: `StoreLoading`, `StoreLoaded(List<ProductEntity>)`, `StoreError(msg)`.

3. `CartBloc`:
   - Events: `LoadCartItems`, `AddToCart(product, qty, variant)`, `UpdateItemQuantity(cartId, delta)`, `RemoveItem(cartId)`, `ApplyCouponCode(code)`, `ExecuteSimulatedCheckout(address, paymentMethod)`.
   - States: `CartLoading`, `CartLoaded(items, subtotal, discount, total)`, `CheckoutSuccess(orderInvoice)`, `CartError(msg)`.

4. `ProfileBloc`:
   - Events: `LoadUserProfile`, `UpdateProfileDetails(name, bio, avatar)`, `LoadOrderHistory`, `ClearLocalCacheStorage`.
   - States: `ProfileLoading`, `ProfileLoaded(user, orders, cacheSizeMB)`, `ProfileError(msg)`.

5. `AdminBloc`:
   - Events: `LoadAdminDashboardStats`, `CreateArticle(post)`, `DeleteArticle(id)`, `CreateEvent(event)`, `DeleteEvent(id)`, `CreateProduct(product)`, `DeleteProduct(id)`, `ToggleUserStatus(userId)`.
   - States: `AdminLoading`, `AdminStatsLoaded(stats, recentLogs)`, `AdminMutationSuccess(msg)`, `AdminError(msg)`.
